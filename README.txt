俳句の裾野 つぶやきBot
======================

X（@haikunosusono）へ、自動でつぶやきます。つぶやきは、次の4種類です。

  ① 毎朝7時 ……「今日の機能紹介」。月〜土は、アプリと同じ今日の兼題。日曜は、機能紹介。
                 （文字数に余裕がある日は、「きょうの定例句会は、10時と22時…」の一行つき）
  ② 定例句会の「あと1時間」 ……（毎日 21時。朝10時の回はいまはお休み：もどし方は tweet.yml の中のメモ）
        例）【あと1時間】22時から、だれでも句会（定例）／お題は「当季雑詠」…／受付中です…／
            ほかの人の句や選評の、無断の公開は禁止です。
  ③ 「はじまりました」 ……（毎日 22時）… 初期設定では、おやすみ（手順8で入れられます）
  ④ お礼 ……（毎日 23時半）
        例）【ありがとうございました】10月10日22時、だれでも句会（定例）の参加は、3人（ほかにボット2名）でした。
            みなさんの句が、ならびました。あす21時に、またお会いしましょう。
        ひらかれなかった回（だれも句を出さなかった回）は、お礼を出しません。

※ ハッシュタグは、文字数に合わせて、うしろから減らします（最低3つ）。
※ お礼に出るのは「人数」だけです。句も、俳号も、点も、つぶやきません（ほかの人の句の無断公開を禁止しているため）。

【お金について（2026年時点で私が確認した範囲）】
Xの投稿APIは、新しい開発者は従量課金です。目安は、リンクなしの投稿が1回 約0.015ドル、
リンクつきが約0.20ドル。最新の料金は、必ずXの開発者ポータルで確認してください。
・初期設定（①②④。リンクなし）…… 平日3回・土日5回ほど。月に約110回 ≒ 約1.7ドル（約260円）
・「はじまりました」も入れると、月に約2.4ドル（約360円）
・リンクを本文に入れる（INCLUDE_LINK=1）と、1回あたりが高くなります。おすすめしません
  （プロフィールにURLを置いておくのがおすすめです）。
GitHub Actions（自動実行）は、公開リポジトリなら無料です。

【手順】
1. https://developer.x.com でログインし、アプリ（Project/App）をつくる。
2. アプリの「User authentication settings」で、権限を「Read and write」にする。
   （App type は Web App / Automated App or bot）
3. 「Keys and tokens」で、次の4つを発行してメモする（権限を変えたあとに発行しなおすこと）。
   ・API Key　・API Key Secret　・Access Token　・Access Token Secret
4. 開発者ポータルの Billing で、クレジットを少額（5ドルなど）購入する。
5. GitHubで新しいリポジトリをつくり、このフォルダの中身をすべてアップロードする。
   （.github フォルダも忘れずに。隠しフォルダなので、フォルダごとドラッグしてください）
   ※ すでにある場合は、post.js と .github/workflows/tweet.yml と menu.json を、上書きしてください。
6. リポジトリの Settings → Secrets and variables → Actions → Secrets に、次の4つを登録：
   X_API_KEY / X_API_SECRET / X_ACCESS_TOKEN / X_ACCESS_SECRET
   （お礼のための人数は、アプリが公開の小さな記録に残します。ログインのための鍵は、要りません）
7. 【大事】アプリ側で、新しい firestore.rules を公開しておく（アプリのフォルダで firebase.cmd deploy）。
   これをしないと、お礼のつぶやきが、人数を読めません（「Firestore 403」と出ます）。
8. （お好みで）Settings → Secrets and variables → Actions → Variables に：
   ・TEI_POSTS = announce,start,thanks …… 「はじまりました」も出す（初期設定は announce,thanks）
   ・INCLUDE_LINK = 1 …… 本文にリンクを入れる（料金が上がります）
9. Actions タブ →「俳句の裾野 つぶやき」→ Run workflow。
   まず dry_run=1 で文面だけ確認。kind を announce / thanks などにすると、その種類の文面を見られます
   （kind=auto は、いまの時刻で決めます）。よければ dry_run=0 で、1回だけ本番投稿。
10. あとは自動です。止めたいときは、Actionsの「…」から Disable workflow。

【パソコンで試す】
  node post.js                                       …… いまの時刻の文面を表示（鍵がなければ投稿しない）
  FORCE_NOW=2026-10-10T21:00:00+09:00 node post.js   …… 時刻を指定して確認（あと1時間）
  FORCE_NOW=2026-10-10T23:30:00+09:00 node post.js   …… お礼（人数は、インターネットから読みます）
  KIND=daily FORCE_DATE=2026-10-09 node post.js      …… 毎朝のつぶやきを、日付を指定して確認

【お礼の人数のしくみ】
定例句会が、定刻にはじまるとき、アプリが、人数（人・ボット）だけの記録（Firestoreの pub/回の名前）を
1回だけ残します。ボットは、それを、公開のアドレスから読んで、お礼の文にします。
（句の内容や、俳号は、この記録に入りません。書きかえや消去は、ルールで禁止してあります）

【兼題データについて】
menu.json は、アプリと同じ計算でつくった、約400日ぶんの「今日の兼題」です。
アプリの兼題が変わったときは、次で作りなおせます：
  node tools/gen-menu.js ../public/index.html 400
